# Delivery Plan

Alloy's delivery strategy is incremental and evidence-first. The aim is to prove
that engineering intent can improve Foundry runs *before* taking on the cost of
deep runtime integration.

## The shape of the plan

1. **Prove value with a projection-only MVP.** The [[mvp]] generates context
   that Foundry consumes through existing prompt mechanisms — no Foundry code
   changes required. If a run guided by Alloy context beats a generic prompt,
   the core thesis holds.

2. **Grow through a product roadmap.** Once value is shown, the [[roadmap]]
   expands capability across Phases 1–6, from intent capture and codebase
   archaeology to native Foundry integration, trace-to-intent learning, and
   multi-intent orchestration.

3. **Phase the integration in parallel.** A separate
   [[phased-integration-plan]] (Phases 0–5) governs how tightly Alloy couples to
   the Foundry runtime, moving from product-local projection toward a full
   learning loop.

4. **Track the work.** A [[specification-backlog]] identifies the documents that
   must be written next, and a short list of [[immediate-next-steps]] names the
   concrete first moves.
